Audited the 22 example projects under `python/examples/` against the three ADK
skills (`adk-multi-agent`, `adk-tool-design`, `adk-safety-callbacks`). Four
parallel read-only passes; findings synthesized and cross-checked here.

## Deliberately NOT auto-fixed — needs a decision (tracked as issues)

### A. Identifier interpolation (table/column names) in SQL
`sql_literal()` escapes string **literals**, not identifiers, and you cannot
bind a table name as a parameter — so the "just use `sql_literal`" advice does
**not** apply here. These need a name validator/allowlist. Blast radius is
bounded by OBO identity (caller's own grants).
- `data-inspector/tools.py` — `delta_bisect` (L112), `delta_bisect_column`
  (L195–201), `version_diff` (L267–273), `audit_lookup` (L296–306),
  `get_table_info` (L66): `table`/`condition`/`column` interpolated verbatim.
- `data-triage-agent/tools.py` — `get_table_lineage` (L87), `find_jobs_for_table`
  (L109), `get_table_info` (L63): `table_full_name` interpolated.
- `contract-parsing-agent/tools/extract_new_contract.py` — `volume_path` passed
  to `Path()`/INSERT with no `/Volumes/` prefix check.

### B. Composition primitive choices (behavior change)
- `customer_triage` — `HandoffAgent` used for a closed mutually-exclusive
  routing decision; `RouterAgent` is the tighter primitive (extra delegation
  round-trip today).
- `entity-resolution-agent` — supervisor↔evaluator retry is a generator-critic
  loop; `LoopAgent` expresses the exit condition structurally vs. relying on
  instruction-following. `HandoffAgent` works; `LoopAgent` is a closer match.

### C. Tool-shape judgment calls
- `customer_triage[_fleet]` — `format_address` is pure string formatting exposed
  (and UC-published) as a tool; the LLM can format directly. Candidate for
  removal.
- `contract-parsing-agent` — `find_contracts_expiring` overlaps
  `query_portfolio(expires_within_days=)`; merge or disambiguate docstrings.
- `explain-my-bill-agent` — `compare_months` is a 3-operation composite
  (coherent domain concept, but violates "one job"; expensive to retry).
- `shortage-intelligence-agent` — `validate_against_market_news` and
  `eligibility-agent`'s PDF parse make **nested LLM calls inside a tool**: not
  traced by `log_agent`, not covered by the outer `max_iterations`/rate limits.
- Missing `attach_resources` on tools touching named UC assets across
  `contract-parsing-agent`, `shortage-intelligence-agent` (manifest correctness
  for `log_agent`).

### D. Safety posture on demo examples (arguably working-as-intended)
- `customer_triage`, `customer_triage_fleet`, `memory_demo` — hardcoded
  `default_principal_id` ("alice"), no per-request principal resolution. The
  code comments acknowledge it; in multi-user deploys every caller shares one
  memory store. Should be a documented deploy blocker or a
  `before_agent_callback` that resolves `Dependencies.Principal`.
- `slack-agent` — in-memory token store + OAuth nonce map with no TTL/eviction;
  misleading baseline if copied to production.
- `apx-builder` — unsanitized `use_case`/`app_name` interpolated into
  **generated code**, and no approval gate on workspace-write/deploy. Real, but
  the fix is a design change (input validation + `before_tool` gate), not a
  one-liner.

### E. Ergonomic / consistency (Minor)
- `max_iterations` unset on most agents. The skill treats it as **optional**
  ("when you want a ceiling"), so blanket-adding it to 22 demos would be
  over-engineering — apply per-agent where a real latency/cost ceiling matters.
- `databricks-skills` scaffold template ships stub docstrings and a
  `description=<placeholder>` that would break A2A routing if copied verbatim;
  and hand-rolls a Genie poll loop without `attach_resources`.

## Explicitly reviewed and found NOT a defect
- **MCP-server bare `raise ValueError` on invalid action** (`jobs.py`,
  `unity_catalog.py`, ~10 sites). The auditor called this inconsistent, but
  `jobs.py` has zero `{"error":...}` returns — bare-raise IS the file's
  convention, and `middleware.py` catches all exceptions into a structured
  `isError=True` envelope. Changing these would fight the codebase's own error
  architecture. Left as-is.

## Exemplary (leave alone)
`zero-ops-diagnostics` (RouterAgent + clamped inputs + escaped filters),
`data-inspector` (verb-first tools, `ToolError`, `require_user_api_scopes` — aside
from identifier interp in A), `bakehouse-agent` (idiomatic RouterAgent over
DataAgents), `shortage-intelligence-agent` guard composition
(`RateLimit`+`prompt_injection_heuristic`+`WatchdogGuard`), `slack-uc-mcp` tool
factories (`attach_resources`, structured errors, `__doc__` override).

## Pre-existing note (not introduced, worth tracking)
`databricks_tools_core.sql.sql_literal` only doubles single quotes; it does not
escape backslashes (unlike `apx_agent`'s `sql_escape`). The fixes in category 1
use the escaping the example already had available; a hardening pass could move
these to `sql_escape` or bind parameters throughout.
