## Cross-plan composition contract (READ before executing the 2nd and 3rd plans)

All three plans were authored against the **current (E2-era) state** of `_wiring.py` and `_models.py`. When you execute the second and third plans, those files will **already have been modified by the earlier slice(s)** — line numbers and the `finalize_agent` body will have shifted. Therefore:

- **Re-inspect before every edit.** The line numbers in each plan are guides as of the E2 baseline, not gospel. Inspect the *then-current* `finalize_agent` / `AgentConfig` / `setup_agent` before applying an Edit; match the real text.
- **Compose, do not clobber.** Each slice ADDS to `finalize_agent` and `AgentConfig`. Never replace the whole function/class — insert your call/field alongside the prior slices'.

### `AgentConfig` (`_models.py`) — additive fields (no collisions)
- E3c adds `guardrails: GuardrailsConfig`
- E3a adds `template: dict[str, Any] | None`
- E3b adds `memory | session | example` backend-config fields

Each is a distinct field; just append yours to whatever the class already has.

### `finalize_agent` (`_wiring.py`) — the intended **composed** order after all three land
```
resolve_agent(module_spec, config, ws=...)        # E3a — BEFORE finalize, at the call sites; builds the leaf from a template when config.template is set
finalize_agent(agent, config, pyproject_path, ws): # ws param added by E3b (optional, backward-compatible)
    apply_config_knobs(agent, config)              # E1: generation knobs + persona overlay
    merge_config_tools(agent, pyproject_path)      # E2: [[tool.apx.tools]]
    apply_config_guardrails(agent, config)         # E3c: before_tool gates + injection heuristic
    attach_declared_memory(agent, config, ws=ws)   # E3b: build store + attach memory tools (before the card snapshot at the caller)
```
- **E3c (Task 3):** insert `apply_config_guardrails(agent, config)` after `apply_config_knobs`. Idempotent via the `_apx_config_guards_applied` sentinel (mirrors E2's `_apx_config_tools_merged`).
- **E3a (Task 2/4):** does **not** change the `finalize_agent` body — it adds `resolve_agent` to `_wiring.py` and updates the call sites (`setup_agent`/`create_app` `agent` becomes Optional; `_load_finalized_agent`; the deploy `_load_agent` site). When executing E3a after E3c, the `finalize_agent` body already has the guardrails call — that's expected, leave it.
- **E3b (Task 1.5):** add the `ws` param to `finalize_agent` and insert `attach_declared_memory(agent, config, ws=ws)`. By the time E3b runs, `finalize_agent` already contains `apply_config_guardrails` (from E3c) — insert memory attachment after it; do not remove the guardrails call. Keep memory-attach **before the card snapshot** (`collect_tools()` in `setup_agent`), same constraint E2's config tools have.

### `ws` threading — keep consistent
- E3a introduces `_ws_for_template(config)` (lazy `_make_workspace_client()` only when a template is configured; graceful degradation to `ws=None`).
- E3b adds a `ws` param to `finalize_agent` for memory-store construction.
- When E3b lands after E3a, **reuse E3a's `_ws_for_template` pattern** (or generalize it to `_ws_for_finalize(config)` covering both template build and memory build) rather than introducing a second, divergent ws-acquisition path. Reconcile at E3b Task 1.5.
